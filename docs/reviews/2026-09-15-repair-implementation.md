# 评测审计后的修复实现

本轮修复针对 2026-09-15 的十题评测及离线故障复现。没有修改原始评测产物、官方 reward 或冻结源码，也没有启动新的模型评测。此前的 4/10 仍是最近一次实测成绩。

## 已实现

| 问题 | 修复后的行为 | 验证 |
|---|---|---|
| 子任务跨越父工具预算 | 派发前检查完整父链；每个后续工具再次检查。已预留且恰好达到上限的调用仍可执行 | 原始故障、祖父预算、边界计数测试 |
| 原生接口截断丢失用量 | 收到累计 usage 即发出用量事件；语义终态仍单独验证，截断响应不会释放不完整工具调用 | DeepSeek 与 Responses 离线截断流、原有接口回归 |
| 交付报告保留已解除失败 | 复用验收门的失败消解规则；显式有效替代的旧失败归入历史，缺理由或缺断言合同的替代仍保留失败 | 有效替代和无依据替代对照 |
| 需求引用空白差异被拒绝 | 只允许空白重排，定位后保存原始用户文本片段；新增和修订共用逻辑 | 换行、制表符、重复登记及数字、路径、大小写反例 |
| Python heredoc 被当成 shell 串 | 识别完整、单独、引用 delimiter 的 `python[3] -` heredoc；末尾额外命令和缺少结束符仍不视为正向行为证据 | 正向程序体和六类 shell 反例 |
| 评测遗漏推理档位 | 支持 `--reasoning-effort`，优先于进程环境和 env 文件；经 Harbor 环境映射传入 ForgeConfig。控制器元数据记录显式值或 provider_default_unknown | 环境覆盖与容器命令生成测试 |
| 每次追加重读整个日志 | 持锁从尾部读取最后记录，必要时向前扩展；保留 sequence/UUID、fsync，拒绝损坏或未终止尾记录 | 大 Unicode 记录、空白/CRLF、过期写入者、损坏及未终止记录 |
| 结束后才得到验收缺口 | 新增只读 `review_delivery`，刷新工作区证据并返回当前验收问题，保留继续修复的机会；最终提交仍终止一次 | 经执行器调用，确认有缺口、未终止、未修改任务或文件 |

系统指导同时要求根据任务选择独立输入、精确来源组件、已观察样例和干净目录交付验证，并禁止为匹配错误输出而放宽预期。这是代理工作指导，不是能够理解任意算法语义的自动证明器。

## 性能对照

使用相同 append、锁和 fsync，旧版整文件校验作为对照，500 个事件、每个约 20 KB。最终代码多检查一个尾部换行字节。单次 Windows 本机测量：

| 指标 | 旧校验 | 修复后 |
|---|---:|---:|
| 最终日志 | 10.15 MB | 10.15 MB |
| 校验累计读取量 | 2,532,059,634 B | 32,628,017 B |
| 追加总耗时 | 20.20 秒 | 9.51 秒 |
| 后 20 次追加中位数 | 56.36 ms | 14.77 ms |
| 拒绝过期写入者 | 是 | 是 |

读取量减少约 98.7%，本次追加总耗时减少约 52.9%。这不是整题运行时间或通过率的提升估计。数据见 [性能结果](D:/projects/forgecode/docs/reviews/2026-09-15-repair-journal-cost.json)。

## 测试与边界

原来不在默认 pytest 收集路径中的六个故障用例已迁入 `tests/runtime/test_audit_regressions.py`。反例和新增交付检查集成测试位于 `tests/runtime/test_audit_controls.py`。测试使用隔离数据目录，未请求真实模型。

最终产品代码的全量运行共 679 项：678 通过，1 个技能测试因假定第一次模型调用必然带工具而失败。新增工具使其 10K 小窗口先发出摘要调用。测试已改为查找实际带工具的请求，仍验证技能目录、正文和工具 schema，未降低产品断言。随后技能与上下文 47 项全部通过；此后未改产品代码，也未再重复全量运行。见 [全量日志](D:/projects/forgecode/docs/reviews/2026-09-15-repair-final-tests.log) 和 [修正后相关回归](D:/projects/forgecode/docs/reviews/2026-09-15-repair-context-tests.log)。此前基础修复版本另有一次 677 项全量通过。

原始六个故障复现已全部通过。新增反例覆盖父链预算、合法/非法 heredoc、引用重排、无依据替代、日志尾部和只读交付检查。`compileall` 与 `git diff --check` 通过。本轮运行平台是 Windows；没有将此前 Linux 回归结果冒充本轮验证。

这些修复消除已复现的运行时缺陷，并提供提交前的诊断机会；它们不能保证代理自动发现视频样例矛盾、算法查表、序列截短或参考程序依赖。`review_delivery` 只汇总已有证据，不执行新的独立测试，不强制自动修复循环。

Heredoc 识别刻意只覆盖可明确界定的 Python 形式，其他复杂 shell 仍保持 unknown；可改用 `python -` 和独立 stdin。推理配置贯穿本地链路不等于证明远程兼容网关支持该值或实际采用该档位；仍需后续真实 wire 和服务端行为确认。此次没有宣称跨 harness 同条件或分数已提升。
