## 成本分析

最终 payload 合计模型 352 次、工具 460 次；含缓存累计输入 12,805,195 token、输出 147,720 token。MIPS 输入 3,540,475；电路 2,574,472；POV-Ray 1,997,902，三题共 8,112,849，约占输入 63.4%。两个显式 compaction 请求已计入模型请求，不另加次数。

这些是 payload 统计，不是供应商完整账单。长上下文反复携带、复杂算法推理和长进程等待的成本来源不同。不能把 1281 万累计输入理解为单次上下文超出 128k，也不能仅用降低预算来掩盖未完成工作。

本次不提高调用/时间预算，不引入第二 verifier 智能体，不增加按题名规则。提示词新增内容会有小幅输入开销，下一轮应检查是否减少无效验证和长循环，不能预先宣称节省成本。

## 已实施的通用机制修改

1. **未调用测试的保守诊断。** 对普通 `python file.py` 检查工作区内的有限大小 AST；若只有测试函数定义、导入和路径设置，没有可见调用，命令仍真实执行，但结果明确指出验证未建立，不登记成功行为证据。不自动运行 pytest，不改写脚本；显式 main/测试 runner 不被该规则拦截。未知语法不猜测。
2. **可执行的输出要求。** `verify.output_checks` 可对最终 stdout JSON 的实际字段进行 eq/ge/le 断言；输出缺失、类型错误、非有限数和未达阈值都会失败。原始进程 exit_code 保留，即 exit 0 与 evidence_valid=false 可以同时成立；兼容旧 evidence 默认字段。期望值和 requirement 仍是调用者声明，不包装为独立事实或权限。
3. **失败不能靠改标签消失。** 原实现按 covers 标签归并失败，不同命令只要声明同一覆盖就能抵消。改为命令、cwd、stdin 和断言签名标识检查；同一个真实检查重跑成功可以解除失败，换弱检查/降低断言不可以。此缺陷由代码审计与回归探针确认，尚不能断言它导致了本轮某一道具体失败。
4. **预算透明与验证方法。** 主模型请求包含来自统一 TurnState 的剩余调用/时间；无新的预算控制器。通用评测说明要求可证伪检查、独立期望、明确阈值和原始要求逐项复核。计划仍为组织功能，不成为执行权限门禁，也没有总结关键词黑名单。

## 风险及验证边界

- 输出断言只能校验实际打印值是否满足声明条件，不能证明指标算法或组件身份本身正确。模型仍可能选错指标或漏掉要求。
- AST 诊断限于明确的静态模式；不是完整 Python 解释器，也不是“空输出即失败”的规则。
- 原始 session、checkpoint 不批量改写；新增 evidence 字段带兼容默认值。
- 新增真实 Python 进程探针已证明测试定义不执行、指标未达阈值不会完成、不同检查/弱断言不能擦除失败；全量跨平台回归后再冻结并重跑。
- 下一轮仍必须保持固定十题、同一数据集摘要、gpt-5.6-luna、并发 6、120/240 调用预算和 1800 秒。达到 5/10 后还需同版本完整确认轮；本轮分析或测试通过不等于达标。
