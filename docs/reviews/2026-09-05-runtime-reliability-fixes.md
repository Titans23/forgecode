# 模型接收、评测分类与验收关联修复

基于 `390af0b` 的工作区修复；未提交或推送，未启动新 benchmark，未修改官方 reward、历史 session 或用户原有未跟踪文件。

## 修复范围

1. **每题先分类，再聚合。** 新增 `TrialAssessment`：唯一主结果、verifier 状态、是否有效计分、观察到的故障。读取 kernel stop_reason 后再确定计分，不再把 empty/incomplete 等计为普通代码失败。Agent timeout 不再同时增加 infrastructure；同一日志的重复副本不重复增加模型用量；布尔/非有限 reward 不计分。保留历史字段，同时新增 raw_pass_count、verifier_scored_count、eligible_trial_count、primary_outcome_counts。旧 infrastructure_failures 是包含模型/验证环境故障的兼容汇总字段，有明确说明，不应再与子类相加。
2. **内核持久化实际请求。** BudgetedModelClient 对每个实际 attempt 在请求前写开始记录，并在成功、失败、重试、取消时写收尾；路由、压缩和主请求共享同一预算和记录机制。内容仅包含 ID、阶段、用量是否已知、耗时、文本长度、工具块状态等元数据，不额外存储原始网络头、凭据或完整流参数。无事件消费者主动记日志时仍能恢复这些事实。
3. **按内容块核对流与最终消息。** 已收到文本时仍能补出 final-only 的完整工具块；按索引和工具 ID 去重，流与 final 内容冲突明确失败。未结束的工具块不被补全猜测；已有语义输出但没有终止原因不能当成成功回答。协议错误前可获取的最终 usage 仍入账。
4. **恢复安全边界。** 部分文本、工具开始或参数片段均关闭自动纠正边界；已完整但所在响应不完整的工具仍明确取消，不执行。空响应/响应协议纠正与工具参数纠正分离计数，仍受既有两次纠正上限和总模型/时间预算约束。已知输出上限触发的纯文本续写保持原有明确续写语义。修正 context_overflow 与 runner 识别名称不一致的问题。没有提高任何评测预算。
5. **验收有稳定身份和执行关联。** 原文引用核对保留；要求解释带稳定 ID 和 model_proposal 来源。计划替换不能悄悄删除已识别要求，旧 session 加载能重建 ID。verify 的输出断言可绑定 requirement_id、expected_source；每条实际证据保留涉及的要求和有执行断言的要求。显式关联的失败跨 revision/epoch 后变为待重验，不因一次无关弱检查而消失；探索性失败不会一律升级成永久要求。
6. **无计划任务与非成功终止。** 启用 reconciliation 的入口不能靠不创建计划绕过要求登记。简单任务可通过 finish_task.acceptance_criteria 登记要求，无须制造多步计划；未计划任务沿用 session journal 持久化。普通最终回答和 finish_task 使用同一完成判定。blocked 缺乏外部证据时明确指出 failed 路径；failed 不要求成功验证或完整产物。

严格验收关联由 TaskPolicy.require_acceptance_reconciliation 显式启用，benchmark 入口已开启；普通既有调用方默认保持兼容。CLI、飞书、MCP、Skills、Hooks、checkpoint 与工具权限入口没有增加第二执行路径。

额外修复全量回归发现的上下文开销问题：新增验收字段使小上下文 Skills 测试提前触发压缩。模型可见的内置工具 JSON Schema 现在去除冗余 title 注解，保留真实 title 属性、类型约束、默认值、示例和验证逻辑；不改变上下文阈值或模型预算。原有两项 Skills 调用回归恢复通过，并新增实例数据保留测试。

## 成本、兼容性与仍然存在的边界

不增加第二智能体或额外后台模型请求。请求日志每次增加两个小型持久事件，有本地 I/O 开销；源引用、要求 ID 和断言字段会增加少量上下文。简单任务第一次登记要求可能被退回以补真实检查，这是显式验收成本，不能预先宣称总体费用下降。

更严格的 partial-response 处理会减少自动继续机会；它保护执行语义，并不等于解决了供应商中断。没有使用实网调用做因果实验，不能断言本轮 incomplete_tool_call 的供应商/网关根因已被确认。

要求 ID 和 expected_source 是可追踪的解释与声明，不是自然语言语义证明。当前机制能拒绝已登记要求缺检查、弱 covers 冒充执行断言等情形，但不能自动证明提取没有漏项、算法选择正确或 expected_source 确实独立。尤其不把模型声称“题面矛盾”自动认定为事实。

本次未实现自动构建策略优化、通用环境依赖指纹、CheckSpec 语义等价替换或完整的自然语言合同编译器。原有未知 process 保守失效和 verify 环境观察边界仍需后续证据驱动的设计；修正测试脚本或重新解释要求时，也不应通过降低阈值来清除原有义务。

因此本次交付是已证实核心缺陷的回归修复，不是“全部设计路线已实现”，更不是已达到连续两轮 5/10。下一轮仍需用户明确要求后才运行，保持固定十题与并发 6。
