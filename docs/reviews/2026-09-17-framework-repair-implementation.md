# 第一批框架缺陷修复

日期：2026-09-17。对应优化路线的第一阶段，保留既有用户修改，未提交或推送，未启动付费 benchmark。

## 改动

1. Harbor 的 supervisor 与 run_forge 两层 Python 入口均使用 `-I` 隔离模式，从安装环境导入；任务 cwd 与任务文件仍保留。避免 benchmark.py 等同名文件和 PYTHONPATH 干扰入口导入。
2. 权限判断仅对明确的普通命令查询/文字输出作有限豁免；真实提权、脚本 stdin、复杂扩展和将输出作为代码执行的管道仍维持保守拒绝。修复 command -v sudo 的误拒绝，没有关闭权限策略。
3. 删除目标分词保留换行边界，下一行变量赋值不再被当成 rm 参数；引号内路径仍作为单个目标。真实宽泛或未解析的递归删除仍被拒绝。
4. 无结构化 output_checks 的检查支持继承原调用及需求，再运行或增加检查；command/stdin/cwd 改动被明确拒绝。完成判定与继承接口使用一致规则，错误提示说明真实可用的恢复路径。有结构化断言的原继承约束不变。

第四项没有实现“任意改写内联检查器后自动视为等价”。没有可序列化断言时无法证明程序等价，允许任意替换会弱化验收。原命令引用的检查脚本可修复后重跑；真正需要改变内联调用时，原要求仍保留未验证状态，提示不再声称可以自动继承解决。

- Linux 一次性容器（网络禁用、源码只读挂载）中，使用 site-packages 导入路径验证 supervisor 到隔离子进程的启动。任务 cwd 同时存在 benchmark.py 和 forge.py，退出码 0。该探针不调用模型、不下载依赖；它验证导入和监督链，不替代真实付费任务成功率验证。

## 边界与后续

本批不包含服务交付工具、验证依赖缓存、证据依赖失效或算法策略改造。它们属于后续阶段。当前没有新 benchmark 成绩，不能声称通过率已经提高。

权限分析仍采用有限、保守的 shell 识别，并非完整跨 shell AST 解析器；未知复杂程序可能仍被拒绝。后续扩展必须继续使用成对正负样例保护执行边界。
