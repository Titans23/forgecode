# Luna 并发二评测后的修复与复测

## 实现

保留单一 TurnRunner、ToolExecutor 和现有不可变验证事件，先迁移验收合同的身份与修订机制，不重写存储，也不针对十道题编写答案或隐藏测试特判。

- 新增 `forge/runtime/check_contracts.py`：统一结构化断言合同身份。新增可选 `source_ref`，新合同在稳定来源引用不变时允许重述 expected_source；旧记录仍严格保留原来源文本，避免把未知来源变化自动当作等价。
- `verify.inherit_checks_from` 从本轮证据账本复制旧断言，自动链接 supersedes，要求 revision_reason。复制结果仍经 schema、权限、执行器和真实进程执行。模型提供的冲突替换在执行前被拒绝，不能降低阈值或改变要求绑定。
- 多个历史来源说明可以作为多个必须同时满足的断言保留，不靠丢弃历史解决冲突。输出断言上限从 20 调整为 128，以容纳真实日志中的 46 项历史断言；仍有确定上限。
- 完成拒绝显示合同不匹配的断言 key、cwd 是否一致、要求绑定是否保留，并给出继承修复入口。
- 相同工作区、环境、验证事实与拒绝原因连续三次提交完成，终止为 `failed/completion_stalled` 并保留产物。新的工作区状态或新的检查证据重置计数，仅改变验证运行 ID 不重置。文本完成与 finish_task 使用相同保护。
- 工具协议错误区分连续与总量：有效执行后恢复局部纠错额度，连续失败遵守配置，仍有总错误上限；真实测试失败与参数协议错误分开。
- Harbor DeadlinePlugin 将实际解析后的逐题 phase timeout 传入 agent。内核使用剩余时间与配置预算中的较小值，通常留 30 秒启动/清理余量；750 秒题内核约 720 秒，1200 秒题约 1170 秒。保持原生外层时限与官方验证流程。

## 验证记录

- Windows 全量复验：622 passed，1 条既有飞书 protobuf 弃用警告，217.75 秒。此前默认临时目录访问受限、随后长路径触发 Windows 路径上限；最终采用较短的独立临时目录。
- 最后合同调整的针对性复验：25 passed，19.67 秒。覆盖实际工具执行、阈值降低/来源变化/要求换绑不能解除失败、多旧记录继承、重复收尾和截止时间适配。
- 真实历史合同回放：POV-Ray 最后引用的 6 个旧记录共 46 项不同合同全部保留；视频题 3 个旧记录共 13 项全部保留。回放仅检查合同关系，没有伪造或重跑任务验证，不能视为题目通过。
- compileall 与 git diff --check 通过。
- Linux 初始测试容器缺少 Git，导致 88 项同源失败；另一次准备阶段遗漏 evals/extensions 导致收集错误。补齐测试运行环境后再做全量检查，不将这些准备错误解释成产品回归。
- Linux 完整环境最终全量：623 passed，1 条既有警告，70.65 秒。Python 依赖使用本地缓存离线安装，Git/patch 通过测试容器包管理器准备。
- 最后执行分派及旧代理循环回归：62 passed，15.04 秒。没有继承请求的 verify 继续由原执行器校验，避免把普通无效参数错误误分类为合同冲突。

## 边界

模型提供的 source_ref、断言和检查器仍不构成独立正确性证明。此次修复降低合同重抄和收尾循环的损耗，不保证视频精度、编译器构建或电路算法正确。没有放宽官方测试、改变评分、延长题目原生时限，也没有删除历史失败。

细粒度环境依赖失效、完整 Requirement/CheckSpec/CheckRun 存储迁移及验证器 uv 引导故障治理尚未完成；未知进程副作用继续保守使证据失效。新成绩必须由复测证实。
