## 本次已实现

### 交付与验收分离

Runner 的自然结束和 finish_task 共用终止路径。未满足验收时返回 partial 和具体原因，取消重复拒绝完成声明的控制循环。CompletionReport 分别保存执行终态、代理自述、调用方验收、当前检查结果、历史检查和 token 统计完整性；终端、飞书、会话日志和 trajectory 输出报告。官方 reward 不由报告推导。

### 任务证据及会话恢复

真实 verify 执行后立即记录 verification_recorded，绑定任务与 turn，不再依赖最终 turn_completed 才保存证据。恢复、跨 turn 的记录保守标为 unknown；数字 revision 恰好相等不能恢复其有效性。当前模型上下文提供最近八条检查摘要，task_get 可查询完整记录。

Session schema 升为 2。旧会话可读取，继续执行必须 fork；新日志追加由操作系统锁与原有日志头检查保护。历史文件不原地迁移。更换协议须 fork，避免继续向原会话写入不同协议状态。

### 模型与请求边界

主模型、路由和只读探索助手按明确 provider 配置构造客户端，接入 Anthropic Messages、OpenAI Responses、DeepSeek Chat Completions。Responses 保留加密推理状态，DeepSeek 保留 reasoning_content。工具参数必须完整解析成对象，且收到成功终止事件后才可交付执行。

记录不可变 model_client_input 快照，并用摘要关联实际 HTTP 请求 body。HTTP 记录不包含认证头、URL 查询参数和客户端密钥属性。请求正文仍可能包含用户内容，应按会话数据管理。显式终止但缺少 usage 可以完成，统计标记不完整；流无终止不能视作成功。

SDK 隐式重试关闭；适配器最多三次尝试，仅在没有语义输出的可重试传输故障上重试。请求流由消费者显式关闭。新增进程内共享健康状态，连续三次可重试失败打开熔断，冷却后仅允许一个恢复请求，恢复失败暂停。这里没有额外收费探测请求；进程重启可重建健康状态，尚无独立的手动恢复命令。

### 检查与要求修订

检查定义保存在证据的 check_spec，并按不含超时的定义生成 check_id；可通过该 ID 原样重跑，不能覆盖其断言内容。历史运行 ID 保留，用于继承和替代关系。模型提出的要求可依据用户原文修订或撤回；保留旧版本、理由和来源，新要求获得新 ID，调用方要求不可由该工具改写。

### 预算与入口

探索助手的模型请求、工具请求、usage 和未知 usage 向根预算归集；根截止时间约束助手运行。现有工具批次仍顺序执行。CLI 增加 provider/model/base-url 配置，评测入口透传原生协议选择，运行依赖锁包含 OpenAI SDK。Harbor 私有 deadline 适配器增加版本、签名及重复安装检查。
