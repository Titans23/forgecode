# ForgeCode 桌面客户端使用指南

## 在这台 Windows 电脑上启动

1. 打开 ForgeCode 仓库文件夹（当前为 `D:\learn_project\forgecode`）。
2. 双击 **`Start-ForgeCode.cmd`**。
3. 等待构建结束、ForgeCode 窗口出现。构建时的命令窗口显示进度，关闭客户端后会退出。

启动入口每次构建当前源码，保证你看到最新界面。它使用仓库已有依赖，不自动下载软件或申请管理员权限。遇到错误时窗口会保留原因和处理提示。

也可以在仓库根目录的 PowerShell 执行：

```powershell
npm run dev:desktop
```

只检查启动依赖、不打开窗口：

```powershell
.\Start-ForgeCode.cmd --check
```

`forge` 命令启动的是终端客户端。旧的安装包不会自动获得本次源码界面更新；本次请使用上面的入口。

## 第一次使用

1. **打开项目**：首页点击「打开项目」，选择你要处理的代码文件夹。项目会保留在左侧列表中，首次打开为只读。
2. **连接模型**：左下角「连接设置」填写服务商、服务地址、模型名称和 API 密钥，按原生确认框提示保存。桌面连接单独管理，不会直接沿用 CLI 的 `.env`。不要在聊天框里粘贴密钥。
3. **授权项目**：需要让 Agent 修改文件或执行命令时，在工作区点击「授权项目执行」并确认所选路径。
4. **创建会话**：选择模型连接，点击「新建会话」。输入目标后按 **Enter** 发送，**Shift + Enter** 换行。中文输入法选字时按 Enter 不会直接发送。
5. **查看结果**：任务运行中可以取消；完成后检查消息和文件 Diff。历史会话、消息与工具记录、项目文件、实时事件都可以展开查看。反向 patch 是供检查和复制的预览。

左下角「使用指南」随时可回看操作说明，并可直接进入连接设置和环境诊断。外观自动跟随 Windows 的浅色／深色应用模式。

## 窗口能打开，但任务无法发送

**当前是开发预览版，严格执行环境仍有未完成的原生验收。** 界面改版和启动成功不代表沙盒已通过验收。

如果顶部提示「执行环境尚未就绪」，点击「查看原因」，或左下角「诊断」→「诊断原生沙盒」。此时可以浏览界面、项目和历史数据；环境未就绪会阻止任务执行。

如果没有环境提示，检查是否已选择模型连接、创建会话并授权项目。正在执行任务时，输入框暂时不可用。模型连接保存成功也不代表外部服务已通过连通性验证。

「安装原生沙盒」涉及系统配置，需要单独确认目标环境和管理员权限；不要把它作为普通启动步骤。本轮界面更新没有执行安装或放宽严格执行策略。

## 常见启动问题

| 提示 | 处理 |
| --- | --- |
| 找不到 Node.js | 按[开发安装文档](development.md)准备锁定 Node 工具链，重新打开终端或资源管理器后再启动。 |
| 缺少本地 Python 环境 | 在根目录执行 `uv sync --locked --all-groups --all-extras`。 |
| 缺少 JavaScript 依赖 | 在根目录执行 `npm ci --ignore-scripts`。 |
| 缺少 Electron | 依赖安装完成后执行 `node node_modules/electron/install.js`。 |
| 构建或资源校验失败 | 保留命令窗口中的错误；按开发安装文档检查固定运行时和资源，不要删除会话数据或绕过完整性校验。 |
| 双击后没有新窗口 | 查看是否已经打开同一客户端；相同数据配置只允许一个实例。旧版启动器曾误隐藏窗口，已于 2026-10-08 修复；若旧实例仍在运行，关闭该 ForgeCode 实例后再用最新入口启动。 |

从零准备环境、离线演示、构建安装包分别见[开发安装与构建](development.md)。普通启动无需重新制作安装包。完整测试的离线演示使用独立测试项目，不消耗模型 API。
