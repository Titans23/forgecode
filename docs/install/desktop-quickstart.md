# ForgeCode 桌面客户端使用指南

## 在这台 Windows 电脑上启动

安装版从开始菜单打开 **ForgeCode**。0.1.3 开始支持可选本机执行模式；先退出旧版，再运行新版 `ForgeCode-0.1.3 Setup.exe` 完成升级。安装版已包含应用运行时与核心 PowerShell/Git/ripgrep，无需另装 PowerShell 7 或 Docker。项目自己的 SDK、编译器和依赖仍需随项目准备。

下面是仓库源码的开发启动方式：

1. 打开 ForgeCode 仓库文件夹（当前为 `D:\projects\forgecode`）。
2. 双击 **`Start-ForgeCode.cmd`**。
3. 等待构建结束、ForgeCode 窗口出现。构建时的命令窗口显示进度，关闭客户端后会退出。

启动入口每次构建当前源码，保证你看到最新界面。已打开的窗口不会自动载入改版；请等任务结束，完整退出 ForgeCode，再双击此入口。它使用仓库已有依赖，不自动下载软件或申请管理员权限。遇到错误时窗口会保留原因和处理提示。

也可以在仓库根目录的 PowerShell 执行：

```powershell
npm run dev:desktop
```

只检查启动依赖、不打开窗口：

```powershell
.\Start-ForgeCode.cmd --check
```

`forge` 命令启动的是终端客户端。源码变更不会自动更新已安装程序；安装版需运行新版安装包，源码版可使用上面的入口。

## 第一次使用

新桌面配置首次启动时会出现原生确认，推荐 **工作区写入限制**；取消则仅浏览且不保存同意。已有配置不自动修改，可在「环境诊断」的 **「切换执行模式…」** 中选择日常模式或高级本机模式：

- **严格沙盒**：保留历史会话与偏好，当前版本不提供 strict 执行，也不将其自动降级。
- **原生沙盒：写入限制**：选择「使用工作区写入限制并重启」。Windows 使用随应用提供的 DSH ACL runner，Linux 使用系统 bubblewrap。读取和网络沿用宿主能力；动态 `.env` 不具有 OS 级读取隔离，动态硬链接不提供 inode 隔离。工作区授权跨会话保留，每次执行的临时资源单独清理；初始化自检失败时拒绝任务。Windows Node 的管道式子进程捕获暂不支持，可使用继承标准流或文件输出。
- **本机执行 · 无 OS 隔离**：选择「使用本机执行并重启」。命令拥有当前用户的文件和网络权限。

确认后客户端正常退出并重启，侧栏持续显示当前模式。已有 0.1.3 安装包只包含此前功能；本次轻量沙盒在源码版中验证，尚未重建安装器。

1. **打开项目**：首页点击「打开项目」，选择你要处理的代码文件夹。项目会保留在左侧列表中，首次打开为只读。
2. **连接模型**：左下角「模型连接」填写服务商、服务地址、模型名称和 API 密钥，按原生确认框提示保存。桌面连接单独管理，不会直接沿用 CLI 的 `.env`。不要在聊天框里粘贴密钥。
3. **授权项目**：需要让 Agent 修改文件或执行命令时，在工作区点击「授权项目执行」并确认所选路径。
4. **创建会话**：选择模型连接，点击「新建会话」。输入目标后按 **Enter** 发送，**Shift + Enter** 换行。中文输入法选字时按 Enter 不会直接发送。
5. **查看结果**：任务运行中可以取消；完成后检查消息和「文件变更」。历史会话、消息与工具记录、项目文件、实时事件都可以展开查看。「运行详情」可查看调用和执行记录；「核对执行状态」只读检查结果，不会重新运行任务。反向 patch 是供检查和复制的预览。

左下角「使用指南」随时可回看操作说明，并可直接进入模型连接和环境诊断。外观自动跟随 Windows 的浅色／深色应用模式。

顶部左侧的侧栏图标可收起或展开导航，不会关闭当前会话或清空输入；旁边的编辑图标返回「新任务」首页。顶部右侧可直接打开项目。连接状态在侧栏底部查看。

## 窗口能打开，但任务无法发送

**当前是开发预览版，严格执行环境仍有未完成的原生验收。** 界面改版和启动成功不代表沙盒已通过验收。

如果严格模式提示尚未就绪，重复诊断或安装不会解除当前版本的边界缺口。可继续只读查看，或明确选择上述原生写入限制／本机执行模式。切换时必须没有活动任务，并确认引擎已退出、清理完成；历史会话保留原策略，请新建会话。切回严格模式走同一入口。

本机模式若仍提示执行或清理未确认，请在工作区「核对执行状态」处理真实遗留状态；切换模式不会抹掉它。模型连接、项目授权和操作审批仍然需要完成。

如果没有环境提示，检查是否已选择模型连接、创建会话并授权项目。正在执行任务时，输入框暂时不可用。模型连接保存成功也不代表外部服务已通过连通性验证。

源码启动不会自动安装系统组件。新打包路径已接入 Windows 首次使用检查：符合全新配置条件时，由应用调起固定安装步骤和正常 UAC；取消后可在设置中重试。PowerShell/Git/ripgrep 由应用私有资源供应。此流程的完整原生验收仍未完成，当前严格执行环境不会因安装成功自动放行；详见[沙盒实施状态](../implementation/sandbox-redesign.md)。

## 常见启动问题

| 提示 | 处理 |
| --- | --- |
| 找不到 Node.js | 按[开发安装文档](development.md)准备锁定 Node 工具链，重新打开终端或资源管理器后再启动。 |
| 缺少本地 Python 环境 | 在根目录执行 `uv sync --locked --all-groups --all-extras`。 |
| 缺少 JavaScript 依赖 | 在根目录执行 `npm ci --ignore-scripts`。 |
| 缺少 Electron | 依赖安装完成后执行 `node node_modules/electron/install.js`。 |
| 构建或资源校验失败 | 保留命令窗口中的错误；按开发安装文档检查固定运行时和资源，不要删除会话数据或绕过完整性校验。 |
| 双击后没有新窗口 | 查看是否已经打开同一客户端；相同数据配置只允许一个实例。旧版启动器曾误隐藏窗口，已于 2026-10-08 修复；若旧实例仍在运行，关闭该 ForgeCode 实例后再用最新入口启动。 |

从零准备环境、离线演示、构建安装包分别见[开发安装与构建](development.md)。普通启动无需重新制作安装包。完整测试的离线演示使用独立测试项目，不消耗模型 API。
