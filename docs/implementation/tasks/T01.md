# T01 · 终端 Harness 与入口组合

依赖 F00；适用架构第 0–3 章。

terminal/evaluation Profile 选择入口与依赖组合；SDK 使用 HarnessSession API。
复用现有 Harness、Journal、权限、预算、取消和清理；Profile 不提升沙盒权限。
安装与平台前置条件统一维护在 [使用指南](../../install/terminal-quickstart.md)。
安装自动初始化用户配置，`forge config setup/set` 提供终端设置；配置检查不调用模型。

相关测试：`tests/test_api.py`、`tests/test_cli.py`、
`tests/implementation/unit/test_user_config.py`、`tests/native/verify_terminal_native.py` 和 `tests/native/verify_installed_cli.py`。
原生测试与真实模型实验分别验证；当前待办见 [progress.json](../progress.json)。

后续交付依次为 E00 会话延迟保存与历史回显、E01 公开基准配置冻结、E02 结果分类与取消、
E03 Journal 轨迹导出、E04 版本比较与训练数据隔离、E05 WSL 真实联调。
每阶段复用现有测试，精简重复用例，验证后单独推送并确认 CI，再继续下一阶段。
E05 模型调用与管理员环境配置需要明确授权；训练任务采集和实际训练不在本轮范围内。
E01 入口使用共享模型配置和固定 Harbor 版本，将官方任务摘要、源码、锁及预算写入实验配置。
相关行为集中于 `tests/benchmark/test_harbor_dataset_runner.py`；原生 Docker 运行与模型联调另行验收。

当前架构改进依赖 F00 审计，按以下顺序实施：

- P1：修复 Explore 后端所有权与受限分发、模型上下文超限分类，将核心离线测试纳入默认 CI。
- P2：提取公共契约与工具路径解析，统一运行环境装配与生命周期，明确会话和回合的状态归属，弃用无效参数。
- P3：保留有界结构化附件、模型能力描述及安全边界上的追加输入；项目级规则按轮加载，移除未显示收益的局部指令自动加载。
- P4：独立读取的有界并行、增量会话投影和可复现的上下文/性能基准。

每阶段的实现和离线验证写入 progress.json；原生验收与模型消融单独记录，未执行不能标为通过。
付费模型消融、需要管理员权限的环境准备仍需明确授权。常驻终端或 worker 由实际性能证据决定，不作为默认重构依赖。
