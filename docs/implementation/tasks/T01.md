## 完整 sandbox 交付

用户选择 Docker 严格模式，保留原生轻量模式。目标是 CLI/SDK 的真实执行闭环，不以独立容器测试代替交付：

1. 固定本机 Linux 镜像身份；非 root、只读根、无宿主工作区/控制目录/socket 直通，默认断网，强制内存、CPU、PID、磁盘、时间与输出配额。
2. 接入现有文件工具、命令、验证、会话恢复与取消；授权输入隔离导入，修改按原文件身份和写范围校验后回写，拒绝路径穿越、链接、凭据和控制数据导出，取消不能造成迟到写入或孤儿进程。
3. 显式网络白名单由边界外代理控制；拒绝直接出网、DNS绕行、私网/宿主服务、重定向和解析变化绕过，不继承模型密钥。策略冻结且能力不满足时拒绝任务。
4. 本机 Docker Desktop 与 Linux CI 实测；另行修复原生临时目录兼容性并补 Ubuntu 22.04/24.04 原生验收。保留失败证据，不把容器验收充作 bubblewrap 原生验收。
5. 安装镜像准备、只读诊断、示例和当前架构说明齐备，能复现隔离失败/成功、资源耗尽、取消清理和完整代码修改任务，供项目演示与面试说明。

威胁边界：任务代码不可信；宿主 OS、Docker daemon、固定镜像和控制器可信。容器共享内核，不宣称能抵御宿主内核或 daemon 漏洞。付费模型调用和管理员设置仍需独立授权。
