## 当前优先队列与验收条件

以 Agent/Harness 实习展示为目标，依次推进：

1. **现有能力审计**：为 HarnessSession、Journal、预算、compaction、取消、工具执行及评测接口列出真实代码/测试、已运行证据和缺口；区分源码存在与当前版本验证。发现已有能力先复用，不新增平行实现。下表为已核对的起点。
2. **小型冻结任务集**：复用现有 runner，冻结真实开源仓库 commit、任务、模型、预算、重复次数、环境与独立判分；先验证原始版本失败、参考修复通过、原通过测试不退化、故障分类和分母，再申请有界模型调用。现有 calculator/todo/order-service 是自建工程夹具，delivery-repair 是已见预实验，不能换名当真实未见任务。参考修复与测试补丁留在评测器侧，不进入 Agent 上下文/工作区。公开已知题和原生环境适配须说明，不宣称官方榜单分数。所有已尝试任务计入完成率，预算耗尽不算成功；另报成功任务耗时/token及双成功配对。当前不新增付费调用，不改写既有冻结实验输入。
3. **一个长程失败闭环**：从真实轨迹选一个失败，以现有 Journal/预算/验证能力复现停止或中断→恢复→核验。done 要求不重放未知副作用、不获得新预算、失败检查保留、成功依赖独立判分，并能从命令与事件重现；不能只演示“有 checkpoint 文件”。
4. **5 分钟 CLI/API 展示**：给出可运行入口、输入、预期结果、失败恢复与证据位置；按 Git 历史核对个人贡献与上游复用。清楚说明 DSH/bubblewrap 边界、平台未验项和模型样本限制，不将接入上游包装成自研 OS 隔离。

## 完整 sandbox 扩展（未完成，移出当前关键路径）

用户要求保持原生轻量运行，取消 Docker 沙盒路线；安装和日常使用不得要求 Docker、镜像或常驻容器服务。目标仍是 CLI/SDK 的真实执行闭环：

1. 使用 Windows/Linux 原生隔离能力；冻结授权读取及写入范围，保护控制目录、凭据和宿主服务，默认断网，验证内存、CPU、PID、磁盘、时间与输出配额。先审计现有 DSH/bubblewrap 实际能力，再选择补齐实现；缺失能力不能标为支持。
2. 接入现有文件工具、命令、验证、会话恢复与取消；授权输入隔离导入，修改按原文件身份和写范围校验后回写，拒绝路径穿越、链接、凭据和控制数据导出，取消不能造成迟到写入或孤儿进程。
3. 显式网络白名单由边界外代理控制；拒绝直接出网、DNS绕行、私网/宿主服务、重定向和解析变化绕过，不继承模型密钥。策略冻结且能力不满足时拒绝任务。
4. Windows 与 Ubuntu 22.04/24.04 原生实测，修复临时目录兼容性。保留失败证据；已撤销 Docker 路线的历史测试不能充作原生验收。
5. 轻量依赖准备、只读诊断、示例和当前架构说明齐备，能复现隔离失败/成功、资源耗尽、取消清理和完整代码修改任务，供项目演示与面试说明。

威胁边界：任务代码不可信；宿主 OS、原生隔离实现、固定工具安装和控制器可信。不宣称能抵御宿主内核漏洞。能力不足时明确拒绝严格任务，不静默提权或回退。付费模型调用和管理员设置仍需独立授权。
