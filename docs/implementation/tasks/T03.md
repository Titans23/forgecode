# T03 · 可扩展 Agent 底座与可验证定制

依赖 F00、T01。保持 Python 内核及权限/取消/清理边界。工具按显式并发声明分组，授权与结算有序、执行体可重叠；独占调用形成屏障。按用户要求移除 Harness 累计预算，保留用量统计、单次操作超时和外部评测截止时间。

交付五个独立检查点：通用 SDK 与 coding 解耦；可信插件与生命周期；多模型与角色配置；插件开发、分层验证及交付包；统一评测与 pi 对照入口。

新增工具执行检查点：批内并行、后端输出分流和多调用终端状态；会话拥有的后台命令与输出/取消工具；按实际文件目标协调编辑。复用同一 Executor、权限、Journal 与进程清理路径，分阶段验收，不把并发上限当累计预算。

插件只在用户显式信任后加载，不宣称隔离恶意 Python。普通 coding 与严格验收策略分离；官方 grader 独立。无工作区 SDK 不启动原生后端，不导入未选择的提供方或产品界面。

验收覆盖插件加载失败/取消/卸载、跨会话状态、模型切换和恢复、独立业务检查、版本绑定、交付包去凭据与重建；三个本地示例仅使用公开接口。真实模型实验、管理员安装、公共 registry 发布及完整原生隔离不在自动执行范围。

实现入口：forge/agents.py、plugins.py、runtime/model_registry.py、validation.py、delivery.py、development.py；评测复用 benchmark/harbor，pi 对照位于 benchmark/comparison。安装验收使用 scripts/check_sdk_install.py，覆盖无 Node 路径的 SDK 完整回合及第二环境复验。公开基准资源不可用、缺少官方预构建镜像或真实模型额度未授权时保持未验证，不补造结果。

实现状态与当前验证见 progress.json；报告留在忽略目录。每个检查点验证后 commit、push，并核对 CI。

当前精简重构依次完成：遗留代码与兼容面清理；统一会话装配并分离通用内核和可选领域能力；统一 Journal 事实与训练导出；收敛 benchmark 并隔离旧 RPC 控制面；收紧分发依赖和架构验收。各检查点独立提交，保留自然语言插件开发、官方 grader、完整含失败/取消的轨迹和历史数据读取。Personal/Robot 等组合通过插件扩展同一运行链路，不能为新领域复制内核。
