## F14 · 限权 IPC、原生授权与应用协议安全

**依赖：** F05, F10, F13。**规范章节：** 10, 16。

**默认文件／职责：**

- `apps/desktop/src/main/ipc.ts`
- `apps/desktop/src/main/approvals.ts`
- `apps/desktop/src/preload/`
- `tests/desktop/security/`

**实施步骤：**

1. 按业务暴露 preload，每个 IPC 校验 sender、frame、origin、schema。
2. 目录注册和高风险审批由 Main 重新取可信详情。
3. 实现 binding nonce／hash／expiry 消费。
4. 禁止导航、webview、远程脚本和任意原生接口。

**新增行为测试：**

- 恶意 iframe／未知方法／伪审批不能获得权限。
- 审批参数变化后旧批准失效。
- 自定义协议 traversal 被拒。
- 项目 HTML 不执行脚本。

**完成标准：**

- Renderer 无任意 RPC／文件／Shell／密钥读回接口。

**验收命令：** F02 建立入口后运行 `python scripts/impl.py verify --task F14`；实际底层命令、平台与结果写入 evidence。F00 在该入口建立前使用第 2 章通用命令。

### Discoveries

- 最初审批测试缺少脚本模型 usage，被原 Harness 正确拒绝；补充协议后真实等待与删除通过。
- `_existing_action` 返回持久结果，审批服务需显式标记 reused；修复后同 action 重试不再消费 token 或执行工具。
- 原 catalog 已有 contract-only workspace.authorize；升级时替换其 payload，而非新增重复键。
  generator 现在拒绝重复 JSON 定义，Python / TypeScript fixtures 保持 50 methods × 4 cases。
- Electron 真正阻止了辅助窗口加载 data HTML；测试记录拒绝，不要求危险页面加载成功。
- 真实 pending 工具仍能处理 RPC health / cancel；杀掉并重启 Engine 后旧 nonce 拒绝，文件保留。

### Decisions

- 保留 PermissionRequest / CLI / Harness 回调接口；内部 ContextVar 绑定最终参数和 tracker。
- 两个 Main-only prepare 方法返回短期 nonce，不向 Renderer 暴露；DB 只留消费 hash。
- 原生确认之后重新查询并复核窗口身份；仅拒绝／仅此次，未增加长期授权。
- 评测默认不接人工批准；显式测试 CLI 的 interactive-approvals 只允许私有 Main test profile。
- 详见 `../adr/014-exact-native-approvals.md`。
