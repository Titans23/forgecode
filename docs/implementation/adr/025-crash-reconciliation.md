Recovery keeps SQLite accepted actions and the native Harness Journal authoritative. Migration 014 appends immutable startup observations under the new Engine epoch. Only already committed, validated Journal records rebuild missing projections. Header/project identity, native session ID, sequence chain, payload hashes and previously projected hashes must agree. Recovery never invokes a model, ToolExecutor, orphan cleanup or an old PID. Legacy unbound tool records explicitly retain whole-Journal scope; turn artifact scans explicitly retain profile scope.

A readonly recovery.inspect method and a workspace panel expose ownership, cancellation, cleanup, conservative deadlines, projection progress and bounded integrity observations. Global reconciling/cleanup barriers prevent new side effects even after a work item is marked indeterminate; the worker waits instead of repeatedly trying to claim blocked work. Cancellation with unconfirmed attempt cleanup yields execution error/indeterminate while preserving the independent grade.

Main keeps at most 256 timed-out request identities; validated late responses cannot corrupt the channel. A timed-out mutation queries its durable action ID once. Later matching submissions resolve the original accepted action before any new mutation is sent. At most 32 unresolved actions are retained. Overflow fails closed for new mutations while necessary cancellation/revocation and readonly inspection remain available; Main does not automatically restart Engine or invent a new accepted task.

The live Main lease is readonly ownership observation, not PID cleanup authority. Windows opens a process handle with synchronization/query rights and verifies creation order; one exact Python/one-file launcher relay is allowed only with actual parent and executable proof. Linux requires the actual parent and pidfd. Engine stops scheduling and requests cancellation when the owned parent handle exits. The optional CLI flag is added only by trusted Main; old CLI/Harness signatures remain unchanged.

Hard Main termination is separate from graceful pipe EOF. On this Windows development machine, actual Node Main hard kill can terminate Engine before cancellation commits. [libuv's Windows process implementation](https://raw.githubusercontent.com/libuv/libuv/v1.x/src/win/process.c) documents its parent-lifetime Job for spawned children; the observed persisted running row is consistent with that mechanism. A new exclusive Engine writer then enters reconciling and unknown cleanup, with the original action ID and no replay. No detached production workaround or clean claim is added. Existing real EOF tests verify graceful cancellation independently.

Desktop resume refreshes readonly health; deadlines use the more conservative monotonic/UTC remainder and never gain time from clock rollback or restart. Deterministic clock tests do not prove actual OS suspend/resume.
