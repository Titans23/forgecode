# ADR 034 — 沙盒执行边界与随包 Shell 运行时

日期：2026-10-08。关联：F28、F31，以及 F01/F08/F10/F11/F12/F27 的既有接入点。

状态：S1 代码已落地，包括私有工具供应、Ubuntu 安装配置、Windows 首次使用和请求传递。实际 Windows 原生 11 pass / 1 fail / 11 blocked；动态新建 `.env` 可读，S3 可行性门禁失败，S2 准入仍关闭。完整接入、切片与测试见 [沙盒改进方案](../sandbox-redesign.md) 和 [S1 证据](../evidence/F28-sandbox-s1-observations.json)。

2026-10-08 补充决定：用户明确要求“只需要安装 forgecode 后即可开箱即用”。正式支持平台的依赖供应、必要系统初始化和首次自检必须由单一产品安装／首次使用流程完成；只诊断缺失后让用户另装软件或复制命令不满足交付要求。

## 问题

提出本 ADR 时，Windows 路径依赖系统固定位置的 PowerShell 7；S1 现已取消该依赖并完成本机固定 SRT setup。能力准入、动态敏感路径和清理仍存在实现或原生证明缺口，仅解决依赖不能解除 strict 阻断。F31 已转移到另一台 WSL/Docker 电脑，其官方执行环境和宿主授权仍需独立实现。

## 决策

1. 保留桌面 strict 默认、Windows 原生日常任务、Ubuntu 原生任务及独立 Harbor 官方容器评测。保持现有 Python Harness/CLI 和 Backend 接口，不引入另一套插件或调度框架。
2. Windows 安装资源增加锁定的 PowerShell 7 ZIP 完整运行时与核心 Git/ripgrep，统一经现有可信资产清单解析；不要求普通用户另装系统运行时或核心工具。源码已改用私有资产，完整依赖校验与实际工具启动已有测试；完整隔离与干净系统验收仍待完成。
3. P0 只提供这一条新的生产 Shell 路径，迁移完成后删除旧路径分支；不添加 5.1/Git Bash/PATH 自动后备。缺失或篡改资源应拒绝启动。
4. 前提 readiness 与逐项能力证明分离。固定可信 verifier 运行真实 canary，证据绑定运行时/平台/策略适用范围；prepare 重新核对实际会话边界后才能对模型开放。不能用导入证据或配置布尔值绕过准入。
5. 文件、Shell、verify 和 Explore 使用同一受限会话与冻结策略；未接入的宿主扩展继续禁用。动态敏感路径和完整清理是 SRT 可行性门禁，不降低现有保护承诺。
6. SRT 的账号/WFP 初始化保留固定 broker 与真实 UAC，并接入首次使用流程；用户无需进入高级诊断或执行命令。已有用户授权有效，不自动修复或卸载共享组件。系统权限确认属于正常安装动作。
7. F31 复用 Harbor 的官方环境，补齐实际网络强制策略、宿主逐请求授权和冻结快照。WSL/Docker 不替代 Windows 或 Ubuntu 原生图形验收。
8. Ubuntu deb 声明 bubblewrap/socat/ripgrep/git 等实际系统依赖，安装流程自动解析；随应用供应 SRT/helper 和私有运行时，按需配置 ForgeCode 专属 AppArmor profile。默认支持系统若仍需手工补依赖或修改系统策略，开箱即用验收失败；不关闭全局保护。
9. 干净系统仅安装 ForgeCode、接受正常系统授权、配置模型并选择项目后，首个受限文件/Shell/Git 任务必须成功。项目 SDK 独立准备；应用核心 Git 不划作项目依赖。联网安装与正常系统权限为基准，企业禁用策略单独报告。

## 参考与未采用的方案

- DSH 提供能力分解、平台后端选择与 Shell 兼容的参考；其 Windows 写入限制不覆盖当前 strict 的敏感读取和网络要求，暂不引入第二后端。
- Pi 提供可替换工具执行和外部容器/微虚拟机的参考；其默认本地执行和 SRT 示例初始化失败回退不作为 ForgeCode 的 strict 行为。
- 直接增加系统 PowerShell 5.1 回退可以减少部分安装步骤，但会引入另一套编码/引用/模块兼容面；随包锁定运行时更符合现有可信资产体系。
- 将所有桌面任务迁往 Docker/WSL 可改变初始化问题，但不符合 Windows 原生目标。QEMU/Gondolin、Landlock 后备和 macOS 不纳入本轮。

上游固定提交、原始链接及适用限制统一维护于 [方案第 2 节与资料表](../sandbox-redesign.md)。不把上游原生结果复制为本项目证据。

## 影响和落地条件

新增 PowerShell 会增加 Windows 包体、许可清单与维护成本；须核验完整依赖和沙盒身份的只读执行权限。现有 RuntimeBindings、FileToolBackend、SrtBackend、CapabilityReport 继续承担各自职责，不新建通用 ExecutionEnvironment 层。

按 S1 双平台依赖与首次使用、S2 证据准入、S3 文件/清理、S4 干净系统开箱即用验收推进 F28；F31 的 S5 代码与无模型检查可独立推进，正式运行仍受原有依赖门禁约束。Windows 10、Ubuntu 22.04/24.04、安装版与 live-eval 结果分别记录。

本 ADR 补充主规范第 1.1 节的安装体验要求，调整第 12、20 章的双平台供应和首次使用方式，并补充第 11 章的实施次序；不降低第 1.4 的威胁模型、第 11 章的保护要求或第 24 章的通过条件。ADR010 等历史决策和证据保留其当时事实。
