# ADR026 — Preserve CLI and provide an opt-in authenticated Web transport

- Status: implemented; unit 149, portable 334, regression 1227 and development Electron 66 checks pass; packaged/native/live-model acceptance blocked
- Task: F26; parent HEAD e37e09a514f3bfdf7888e45ea25a3dcc10d961b3

Original CLI signatures, tool definitions and meanings are measured against a committed F25 golden fixture. New engine/sandbox/eval commands lazily delegate to the actual module entry points. HTTP is imported only by the explicit web command. CLI and ApplicationServices both reach the existing Conversation.stream workspace_execution OS lock, independent of Desktop and profile database paths.

Unknown configuration values remain on load and on legitimate permission grants. Permission persistence preserves root fields, the original version and matching rule extensions; unrecognized entries stay opaque. A malformed existing document is preserved and cannot be overwritten by a new grant. Actual authorization tests first reproduced data loss and then verified preservation.

Legacy sources are scanned readonly without SessionStore.list (which writes its index). prepare validates physical file boundaries, native Journal identity/chain and quotas, then atomically stages an exact-byte backup and mapping preview. import requires the current canonical SHA, verifies backup integrity and imports immutable profile-bound mapping rows plus journal.projected observations under an imported source namespace. Repeated imports reuse mappings. Missing/corrupt backups and changed sources fail visibly. Imported observations do not create runnable sessions, accepted turns, usage ledger entries or grades. This prevents historical or foreign evidence from gaining native execution authority; original files and unknown values remain intact.

The optional web extra pins aiohttp 3.14.4 with uv distribution hashes and actual license metadata. The trusted CLI binds only 127.0.0.1 at a random port. A per-start 256-bit one-time credential is printed separately from the URL and posted through a fixed login form. The resulting HttpOnly/SameSite cookie is combined with exact Host/Origin checks, CSRF, single nonce/time headers, a bounded replay window, bounded JSON, scoped authenticated fetch SSE and controlled artifact IDs. No credential enters URL/static JavaScript/argv/project files. Default CLI/Desktop creates no HTTP listener.

The HTTP host uses the existing RpcServer, scheduler, ApplicationServices and DTO validation. Its explicit allowlist includes implemented renderer methods and exactly two public named wrappers already used by Desktop: session.create_default and session.submit. Those two catalog methods remain Main-only on stdio; the trusted HTTP host forwards them like named Desktop IPC. Other Main-only methods, workspace authorization, credentials, native approvals and shutdown reject with DESKTOP_OR_CLI_APPROVAL_REQUIRED before business execution. This is a narrow host proxy, not a client-supplied role elevation.

Desktop and Web share the React UI, DTO semantics and reducers. Node retains AJV runtime compilation; browser validators are generated by the same pinned AJV into standalone code, with only three reviewed helper imports. Generated output is checked for drift and fixture verdicts match Node with Function construction denied. This follows [AJV standalone guidance](https://ajv.js.org/standalone.html) and permits a self-only CSP without unsafe-eval. The optional validator/HTTP chunk is loaded only by Web; the Desktop entry stays about 299 kB. The optional chunk is about 2.27 MB (177 kB gzip); no performance guarantee is claimed.

HTTP mutation uncertainty retains method/action/hash bindings and reconciles through readonly action.get, without automatically reissuing a mutation. SSE batches remain pending until acknowledged; reconnect repeats unacknowledged delivery and the shared reducer deduplicates it. Cursor expiry requires a fresh snapshot and a history-gap marker. Stream and replay quotas fail visibly.
An expired batch acknowledgement closes the old scoped subscription and queries the actual session snapshot before starting a new stream. Intentional abort does not create a false network gap. The added real short-TTL socket test reproduces the expired ack, then verifies a future explicitly submitted task arrives through the renewed stream without automatic task replay.

Actual tests use the real HTTP server, sockets, SQLite, Journal, Harness tools, private Desktop Engine and Chromium UI. Offline scripted model clients are explicitly identified. Early tests caught CJS conditional-export incompatibility, the Main-only wrapper restriction, and login forms with null Origin under no-referrer. Conditional default exports and the narrow host allowlist fixed the first two. Referrer-Policy same-origin retains exact Origin checks; null Origin stays rejected. [Origin header documentation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Origin) supports this browser behavior. No permissive CORS or CSP relaxation was introduced.

Windows 11/Ubuntu/native sandbox/installed-client/manual dialog acceptance and paid model/public benchmark runs remain blocked by existing environment and authorization gates. The Web CLI defaults to strict and execution stays blocked until F28 supplies a verified native backend. Web credentials are trusted CLI process memory, not a claimed protected OS credential store. Repository development UI assets are used here; standalone installed composition belongs to F27/F28.
